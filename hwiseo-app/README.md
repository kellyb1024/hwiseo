# 휘서 (輝敍) — 프로토타입

사진 한 장을 보고 질문을 던져 그 안의 기억을 다시 꺼내는 대화형 앱.

## 실행

```bash
npm install
npm run dev        # http://localhost:3210
```

## API 키

```bash
cp .env.local.example .env.local   # 그리고 키를 채운다
```

키가 없으면 **목 모드**로 돌아간다 — 미리 준비된 질문으로 화면 전체가 동작한다.
시연 중 네트워크나 API가 죽어도 멈추지 않게 하려는 장치다.

## 폰에서 보기

맥과 폰이 같은 와이파이면 폰 브라우저에 **http://192.168.35.229:3210**
(주소가 바뀌면 `ipconfig getifaddr en0` 로 확인)
사파리 → 공유 → **홈 화면에 추가** 하면 주소창 없이 앱처럼 뜬다.
고치면 폰에서 새로고침만 하면 반영된다.

넘겨줄 용도의 **단일 HTML** 은 `node tools/build-standalone.mjs` →
`../prototype/휘서-프로토타입.html` (파일 하나, 서버 불필요, 대화는 미리 준비된 내용).

## 순서

1. **앱 프로토타입 완성** ← 지금 여기 (아이콘 · 스플래시 · 온보딩 · 홈 · 대화 · 이야기 · 푸시 배너)
2. 전시용 짧은 버전은 그 뒤에 별도로. 코드에는 `?turns=N` 만 남겨두었고 UI에서 다루지 않는다

## 화면 전환기 (개발용)

왼쪽 위 패널에서 화면을 바로 띄운다. **키보드 1~7** 로도 전환된다.

| 키 | 화면 |
|---|---|
| 1 | 스플래시 |
| 2 | 온보딩 · 불 켜기 (자는 캐릭터를 누르면 눈을 뜬다) |
| 3 | 온보딩 · 인사 |
| 4 | 온보딩 · 이름 · 프로필 색 |
| 5 | 온보딩 · 알림 주기 |
| 6 | ① 대화 목록 |
| 7 | ① 대화 · 첫 질문 |
| 8 | ① 대화 · 진행 |
| 9 | ① 대화 · 생각 중 |
| s | ① 대화 · 이야기 완성 |
| d | ② 서랍 |
| m | ③ 나 |
| h | 휘서 프로필 |
| 0 | 푸시 — iOS 잠금화면 위 알림 배너 (OS UI라 앱 테마와 무관, 탭하면 앱 열림) |

## 구조 — 탭 3개

| 탭 | 무엇 | 왜 |
| :-- | :-- | :-- |
| **대화** | 사진 한 장 = 대화방 하나. 목록에서 골라 들어간다 | 캐릭터는 하나지만 **대화는 사진마다 분리**된다. 한 방에 몇 달치가 쌓이면 못 읽는다 |
| **서랍** | 완성된 이야기 카드 그리드 | 대화는 시간의 흐름, 서랍은 **결과를 다시 읽는 곳** |
| **나** | 이름 · 프로필 색 · 알림 주기 · 데이터 | |

**휘서 프로필**은 대화 목록 우측 상단 또는 대화 헤더에서 연다.
가상 데이트 앱의 '호감도'에 해당하는 자리를 **불꽃 단계**가 맡는다 —
함께 꺼낸 이야기 수만큼 불이 자란다.

4~7은 샘플 데이터로 채워지므로 사진을 올리지 않아도 화면을 볼 수 있다.
숨기려면 `?dev=0`.
URL로 바로 열려면 `?screen=chat3` (id는 위 표의 화면 id: splash, ob-light, ob-1, ob-name, ob-freq, list, chat1, chat3, thinking, story, drawer, me, hwiseo, push).

## 테마 실험 (스플래시 · 온보딩 · 대화)

패널 하단 THEME 또는 `?theme=`:

| 값 | 무엇 |
|---|---|
| `base` | 지금 디자인 (기본) |
| `pixel` | 픽셀 미연시 × 닌텐도 2001 플레이트 구조, 색은 휘서 primary(노랑)/secondary(보라 밀랍) 치환 |
| `n64` | 같은 구조에 `DESIGN-nintendo-2001.md` 원본 팔레트 그대로 |

폰트는 Galmuri (CDN), 캐릭터는 `public/character.svg` (= `design/character/hwiseo-character-final.svg`).
CSS는 `globals.css` 맨 아래 "픽셀 테마" 블록, JSX는 `page.jsx`의 `theme !== 'base'` 분기.
스플래시·온보딩은 JSX 그대로 두고 `.device.px` 스코프 CSS로만 덮는다 (캐릭터만 `src={charSrc}`로 SVG 교체). 탭·서랍·나·이야기 화면은 아직 기본 디자인.
캡처: `../design/screens/theme-experiment/` (`onboarding-{pixel,n64}.png` 5컷 스트립, `chat-*.png`).
역할 규칙: 노랑(또는 signal orange)은 **누르는 곳에만** — 보내기·워드마크·게이지. 블러 그림자 없이 베벨만.

## 캐릭터

원본 그림: `design/character/hwiseo-character-v1.png` (사용자 작업)
앱에서 쓰는 것은 `app/Char.jsx` → `public/character.png` (흰 배경 제거 + 여백 정리본)

| 파일 | 쓰임 |
| :-- | :-- |
| `public/character.png` | 화면 안의 캐릭터 전부 |
| `public/avatar.png` | 프로필 (정사각 512, 투명) |
| `public/icon-512.png` · `icon-192.png` | 앱 아이콘 (노랑 바탕) |

### 아직 못 한 것 — 불꽃 진화
`Char` 는 `level` 을 받지만 **지금은 무시한다.** 그림이 한 종뿐이기 때문.
같은 화풍으로 불꽃 단계만 다른 그림 4~5장이 생기면 그때 파일만 갈아끼우면 된다.
의도: 답할 때마다 불꽃이 커진다 → **불을 켜는 것은 휘서가 아니라 사람의 기억.**
대화 화면은 메시지마다 아바타가 붙는 구조라, 그림이 채워지면 스크롤을 올릴 때
불이 자란 과정이 그대로 보인다.

### 아이콘을 다시 만들려면
`design/character/` 의 원본을 바꾸고 아래를 다시 돌린다 (Pillow 필요).
흰 배경 제거 → 여백 정리 → avatar / icon-512 / icon-192 / character 생성.

## 휘서 프로필 사진

`public/avatar.png` 를 **덮어쓰면 바로 반영된다.** (정사각형 권장, 400×400 이상)
지금 들어 있는 것은 자리만 잡아둔 임시 이미지다.
쓰이는 곳은 두 군데 — 인사 화면(104px)과 대화 헤더(50px). 둘 다 원형으로 잘린다.

## 턴 제한

턴 수는 디자인이 아니라 런타임 파라미터다.

- `http://localhost:3210` — 제한 없음 (앱 기본)
- `http://localhost:3210/?turns=3` — 3턴 후 자동으로 이야기 생성 (전시 체험판)

## 구조

```
app/page.jsx            화면 전체 (언어 → 인사 → 사진 → 대화 → 이야기)
app/api/ask/route.js    다음 질문 생성
app/api/compose/route.js 한 줄 정리 + 이야기
lib/prompts.js          ★ 프롬프트. 이 파일이 이 프로젝트의 본체다
lib/claude.js           Claude 호출 (프롬프트 캐싱 적용)
```

**프롬프트는 코드가 아니라 데이터다.** 질문의 품질을 바꾸려면 `lib/prompts.js`만 고친다.

## 사진 처리

- 폰에서 긴 변 1568px / JPEG 0.8로 축소해 전송 (원본 4~8MB → 300KB 내외)
- EXIF 회전은 `createImageBitmap({imageOrientation:'from-image'})`로 보정
- 서버에 저장하지 않는다. 메모리에만 있다가 사라진다
