## 0. 두 개의 팔레트가 있다

| | 무엇 | 어디서 왔나 |
| :-- | :-- | :-- |
| **UI 팔레트** | 앱 화면의 색 | 손생님 레퍼런스식 Main / Sub / Grayscale 3층 구조 |
| **캐릭터 팔레트** | 일러스트 안의 색 | `design/character/hwiseo-character-v1.png` 에서 추출 |

**둘은 완전히 같지 않다.** 캐릭터는 그림이라 UI보다 부드럽고 탁하다. 억지로 맞추지 않는다.
다만 **어긋난 지점을 알고 쓰는 것**과 모르고 쓰는 것은 다르므로 4장에 정리했다.

| 토큰 | HEX | 쓰이는 곳 |
| :-- | :-- | :-- |
| `--main` | `#FFD54A` | 내 말풍선, CTA 버튼, 활성 탭 인디케이터 |

## 4. 캐릭터 팔레트 (일러스트 실측)

| 자리 | HEX | 비고 |
| :-- | :-- | :-- |
| 왁스 본체 | `#EDE2E6` | 거의 흰색에 가까운 연보라 |
| 촛농 (진한 쪽) | `#B49ACE` 계열 | 흘러내린 부분 외곽 |
| **아웃라인** | `#4B374B` | 검정이 아니다. 자주빛 도는 짙은 회보라 |
| 눈 · 불꽃 코어 | `#FAC754` | UI 노랑보다 **살짝 어둡고 탁하다** |
| 불꽃 바깥 | `#B49ACE` | UI 보라보다 **훨씬 연하다** |

### ⚠️ UI와 캐릭터의 어긋남 — 알고 쓸 것

| | UI | 캐릭터 | 차이 |
| :-- | :-- | :-- | :-- |
| 노랑 | `#FFD54A` | `#FAC754` | 캐릭터 쪽이 약간 어둡다. **나란히 놓으면 미세하게 다르게 보인다** |
| 보라 | `#7B5CD6` | `#B49ACE` | 캐릭터의 보라는 훨씬 연하다. UI의 진한 보라는 캐릭터에 없는 색 |

**대응:** 지금은 그대로 둔다. 캐릭터는 그림이고 UI는 인터페이스라 역할이 다르다.
단, **아이콘처럼 둘이 맞닿는 자리**(노랑 배경 위의 캐릭터)에서는 노랑 두 개가 겹쳐 보이므로
배경을 `#FFD54A` 로 통일했다. 캐릭터를 새로 그릴 때 눈·불꽃을 `#FFD54A` 로 맞추면 완전히 정리된다.

## 5. 인쇄(CMYK) — 패널 · 영수증 · 사인물

화면은 RGB, 인쇄는 CMYK다. **그대로 나오지 않는 색이 있다.**

| 색 | 인쇄 결과 | 참고 CMYK* |
| :-- | :-- | :-- |
| 노랑 `#FFD54A` | ⭕ **잘 나온다.** 노랑은 잉크 원색 | C0 M17 Y71 K0 |
| 연보라 `#EDE7FF` | △ 나오지만 **더 희미해진다.** 종이색에 묻힐 수 있다 | C7 M9 Y0 K0 |
| 진보라 `#7B5CD6` | ⚠️ **탁해진다.** 채도 높은 보라는 CMYK 색역 밖 → 회보라로 떨어짐 | C43 M57 Y0 K16 |
| 캐릭터 아웃라인 `#4B374B` | ⭕ 무난 | C0 M27 Y0 K71 |
| 잉크 `#1D1B22` | ⭕ 무난. 리치블랙 권장 | C14 M20 Y0 K87 |

\* 단순 변환한 **참고값**이다. 실제 인쇄는 종이·프로파일에 따라 달라지므로
인쇄 들어가기 전에 **업체 프로파일로 다시 변환하고 교정쇄를 볼 것.**

**가장 위험한 것은 캐릭터의 불꽃 바깥 보라**다. 화면에서 예쁜데 종이에서 칙칙해지는 전형이다.
인쇄물 작업 시 보라만 별도 값을 잡는다.

## 7. 코드에서 쓰는 법

```css
/* 새 색을 하드코딩하지 말 것. 반드시 토큰으로 */
background: var(--main);
color: var(--ink);
border-color: var(--line);
```

토큰이 없는 색이 필요하면 **먼저 이 문서에 추가하고** `globals.css` 에 넣는다.
