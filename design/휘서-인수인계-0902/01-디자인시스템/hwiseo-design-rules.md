# 휘서 디자인 규칙 v1 (초안)

> 2026-08-26. 화면 설계·코드가 전부 이 문서를 따른다.
> **적용 범위: 챗봇 앱 하나.** 기준은 **모바일**이다.
> 전시 부스는 같은 앱의 3턴 체험판을 보여주는 자리이지, 별개의 화면이 아니다.
> 출처: Nothing 디자인 스킬(조판 규율) + Microsoft Teams UI Kit(색·목소리 구분) + 휘서 세계관.
> 원본 추출은 `design/ref/teams-kit-notes.md`.

---

## 0-0. 작품과 전시는 다른 것이다 ★ (2026-08-26)

이 구분이 흐려지면 모든 결정이 흔들린다.

| | **졸업 작품** | **졸업 전시** |
| :-- | :-- | :-- |
| 무엇 | **챗봇 앱 그 자체** | 그 작품을 보여주는 자리 |
| 형태 | 모바일 앱 (PWA) | 부스 · 패널 · 체험 |
| 평가 대상 | 문제 정의 · 해결 과정 · 구현 수준 · 결과 | 관객과의 **인터랙션** |
| 대화 길이 | 제한 없음 | **3턴 체험판** |
| 푸시 알림 | 있음 (주 1회) | 없음 |
| 사용자 | 본인 폰에 설치한 사람 | 부스 앞에 선 관람객 |

**전시의 3턴은 작품의 축소판이지 작품이 아니다.**
관객이 작품을 구경만 하면 인터랙션이 없으므로, 짧은 체험판을 부스에 둔다.

→ 따라서 **디자인의 기준은 모바일 앱이다.** 부스 화면은 그 앱을 보여주는 것이지 별개 화면이 아니다.
→ 그리고 **포트폴리오에 실리는 것은 앱**이다. 부스 사진이 아니라.

---

## 0. 이 문서가 답하려는 것

"AI 티가 나는 화면"의 원인은 대개 셋이다.

1. **모든 요소가 비슷한 크기로 고르게 놓임** → 위계가 없어 평평하다
2. **채도 높은 브랜드색을 넓게 칠함** → 중간 명도 단계가 없어서 그렇게 된다
3. **그라데이션·글로우·둥근 카드로 빈 곳을 메움** → 절제가 없다

아래 규칙은 전부 이 셋을 막기 위한 것이다.

## 1. 화면의 골격 — 일반 웹 채팅과 같다

ChatGPT · Gemini · Claude 모바일과 같은 형태다. 다만 **사진이 위에 고정되어 있다**는 점이 다르다.

```
390 × 844

┌─────────────────────────┐
│                         │
│   ┌─────────────────┐   │
│   │                 │   │
│   │      사진        │   │  ← 상단 고정
│   │                 │   │
│   └─────────────────┘   │
│   2019 · 03             │
│                         │
│  ┌────────────────────┐ │
│  │ 그때 무슨 냄새가     │ │  연보라 면 #201A2E
│  │ 났는지 기억나세요?   │ │  글자 #C9BCEA
│  └────────────────────┘ │
│                         │
│      ┌────────────────┐ │
│      │ 비 오고 난 뒤    │ │  앰버 채움 #E9A24A
│      │ 흙냄새 같은 게   │ │  글자 #100D16
│      └────────────────┘ │
│                         │
│ ─────────────────────── │
│  답을 적어주세요      →  │  ← 하단 고정
└─────────────────────────┘
```

**말풍선 원칙 (2026-08-26 확정)**

일반 채팅과 같다 — **보내는 쪽만 색을 채운다.**

| | 자리 | 면 | 글자 |
| :-- | :-- | :-- | :-- |
| **사람의 답** | 오른쪽 | **앰버 채움** `#E9A24A` | 어두운 `#100D16` |
| **휘서의 질문** | 왼쪽 | 연보라 면 `#201A2E` | 연보라 `#C9BCEA` |

- 사람의 말이 문자 그대로 **켜진 등불**로 보인다. 화면에서 가장 밝은 것이 사람의 말이다
- 연보라는 채팅의 '흰 종이' 자리를 맡으면서 **동시에 기계의 색**이라는 의미도 유지한다
- 대화가 진행될수록 앰버 면이 늘어난다 → **색 규칙이 설명 없이 증명된다**
- 채도 높은 색은 앰버 말풍선 하나뿐. 나머지 원색은 1px 선·입력 커서에만

**세 층 (Nothing 3-layer rule)**

| 층 | 무엇 | 처리 |
| :-- | :-- | :-- |
| **1차** | 사진, 그리고 지금의 질문 | 화면에서 가장 크고 가장 밝다 |
| **2차** | 지난 대화 | 명도를 낮춘다. 크기는 그대로 |
| **3차** | 연도·턴 표시·안내 | 12px, 가장 어두운 회색, 가장자리로 |

**스퀸트 테스트:** 눈을 가늘게 떴을 때 사진과 현재 질문만 남아야 한다.

### 레이아웃 규칙
- 사진은 **위에 고정**되고 대화가 그 아래로 흐른다. 사진은 스크롤과 함께 사라지지 않는다
- **사진을 카드에 넣지 않는다.** 어둠 위에 그대로 떠 있는다 (Nothing: "가장 중요한 요소를 박스에 넣지 말 것")
- 말풍선은 좌(휘서)·우(사람) 비대칭. 그 외 요소를 가운데 정렬하지 않는다
- 대화가 길어지면 **사진이 축소되되 사라지지 않는다.** 사진이 화면을 떠나는 순간 이 앱은 그냥 챗봇이 된다

## 2. 색

### 2-1. 램프 — 비어 있던 중간 단계를 채운다

기존 팔레트는 어둠 `#100D16`과 연보라 `#B3A5DC` 사이가 비어 있었다.
중간이 없으면 면을 칠할 때 원색을 쓰게 되고, 그게 촌스러움의 원인이다.
Teams 다크 테마 램프의 명도 간격을 우리 색상환에 옮긴다.

```
어둠            #100D16   배경. 모든 것의 바닥

기계 (연보라)                      사람 (앰버)
--fg      #C9BCEA  질문 글자        --fg      #E9A24A  말풍선 면 ★
--fg-dim  #B3A5DC  기계 원색·라벨    --on      #100D16  앰버 위 글자
--bg      #201A2E  질문 말풍선 면 ★  --line    #8A5F28  얇은 선
--line    #6E63A0  얇은 선·커서

무채색
--paper   #EFEAF2   본문
--muted   #8C839B   보조
--dim     #4A4356   가장 어두운 글자. 라벨·연도
--rule    #221E2B   경계선
```

★ 표시가 말풍선이다. **면을 가진 것은 이 둘뿐이다.**



### 2-2. 사용 규칙 — Teams에서 그대로 가져온 것

> Teams 원문: *"Use sparingly. In general, reserve brand colors for orientation, selected states, and live activity."*

1. **면이 목소리를 구분한다.** 글자색만 바꾸지 않는다
2. **채운 면은 사람의 말 하나뿐.** 앰버 말풍선이 화면에서 가장 밝다
3. 기계의 말은 **어둠에 가까운 연보라 면** — 있는 듯 없는 듯하다
4. **그 외 채도 높은 색은 극소 면적에만.** Teams는 선택 표시가 **2×48px 막대** 하나였다
   → 1px 선, 입력 커서에만
5. 대화가 진행될수록 앰버 면이 늘어난다 → **색 규칙이 설명 없이 증명된다.**
   이것이 이 화면의 유일한 서사 장치

### 2-3. 금지
- 그라데이션 · 그림자 · 글로우 · 블러 없음 (등불 모션은 예외이며 그것 하나뿐)
- 오류·경고를 색으로 말하지 않는다 — **Teams 경고색 `#EAA300`이 우리 앰버와 거의 같다.**
  오류는 문장으로 말한다
- 라이트 테마 없음. 대신 모든 색을 명시적으로 칠한다

## 3. 타이포

### 3-1. 서체 — 두 목소리를 서체로 가른다

| 역할 | 서체 | 왜 |
| :-- | :-- | :-- |
| 기계의 질문 · UI | **Pretendard** | 체험 없는 존재의 말. 균질하고 정확하다 |
| 사람의 이야기 | **Noto Serif KR** (또는 고운바탕) | "이건 내 말"로 읽혀야 한다 |
| 연도 · 턴 · 시각 | **IBM Plex Mono** | 계측된 것. 극소량 |

한 화면에 **2패밀리까지.** (질문 화면 = Pretendard + Mono / 이야기 화면 = 명조 + Mono)

### 3-2. 스케일 — 6단계, 행간은 전부 4배수

**390px 폭 기준.** 모바일이 원본이고 이 값이 부스에서도 그대로다.

| 역할 | 크기 / 행간 |
| :-- | :-- |
| 질문 | **22 / 32** |
| 이야기 (명조) | 18 / 30 |
| 확인 문장 | 17 / 26 |
| 입력 · 답변 | **16 / 24** |
| 안내 · 보조 | 14 / 20 |
| 라벨 | 12 / 16 |

일반 모바일 채팅과 같은 크기다. 크게 만들어야 하는 것은 화면이 아니라 **부스 사인물**이다.

### 3-3. 굵기 — 위계를 만들지 않는다

> Teams 원문: *"Don't use bold to create hierarchy in your text. Instead, use a different shade of grey and the SemiBold weight."*

- 위계는 **크기 + 명도**로 만든다. 굵기로 만들지 않는다
- 굵기는 **Regular 하나.** 필요하면 SemiBold 하나만 추가
- 명조/고딕이 이미 목소리를 나누고 있으므로 굵기까지 의미를 주면 과하다

### 3-4. 조판
- 한 줄 **30자 이내**
- 질문 등장은 **페이드 400ms 이상.** 타이핑 애니메이션 금지 (재촉하는 느낌)
- 새 크기가 필요해지면 대개 **간격 문제**다. 거리를 늘려서 해결한다

## 4. 간격 — 4px 배수, 거리가 의미다

```
4 · 8 · 12 · 16 · 24 · 32 · 48 · 64 · 96
```

| 거리 | 뜻 |
| :-- | :-- |
| 4–8 | 붙어 있다 (숫자와 단위, 점과 라벨) |
| 16 | 같은 무리 |
| 32–48 | 새 무리가 시작된다 |
| 64–96 | 새 맥락 (사진 ↔ 대화) |

**구분선이 필요하다고 느껴지면 간격이 틀린 것이다.**
경계선은 입력 영역 위 1px 하나로 충분하다.

### 컨테이너 — 가벼운 것부터
1. 간격만으로 (기본)
2. 1px 선
3. 면 ← 말풍선 둘만
4. 테두리 있는 카드 ← **쓰지 않는다**

모서리 반경 **4px**. 알약형은 쓰지 않는다.

## 5. 파격은 화면당 하나

Nothing 규칙: 한 화면에 패턴을 깨는 지점을 **정확히 하나**만 둔다. 없으면 무미건조하고, 둘 이상이면 산만하다.

| 화면 | 파격 하나 |
| :-- | :-- |
| 대기 | 어둠 속 등불 모션 (유일한 움직임) |
| 소환 | 큰 QR — 화면에서 가장 밝은 흰 면 |
| 확인 | 사진이 처음 나타나는 순간 |
| 대화 | 앰버 말풍선 — 화면에서 유일하게 채워진 밝은 면 |
| 이야기 | 명조 — 이 화면에만 등장한다 |
| 종료 | 등불이 위로 떠오름 |

## 6. 모션

- 지속 **150–250ms** 미세 / **300–400ms** 전환
- 이징 `cubic-bezier(0.25, 0.1, 0.25, 1)`. **스프링·바운스 금지, 선형 금지**
- 등장은 2속성 이상 (투명도 + 이동)
- 위치보다 **투명도**를 선호한다. 사라지는 것은 밀려나지 않고 흐려진다
- `prefers-reduced-motion` 존중
- 로딩은 스켈레톤 금지 → **점 세 개** 또는 등불의 미세한 흔들림

## 7. 안티패턴 — 하지 않을 것

Nothing + Teams에서 온 것을 우리 맥락으로 합쳤다.

- 토스트 팝업 ✗ → 상태는 **인라인 텍스트**로 (Teams: 에러는 입력창 바로 아래)
- 스켈레톤 로딩 ✗
- 그라데이션 · 그림자 · 글로우 ✗
- 채워진 아이콘 · 여러 색 아이콘 · 이모지 ✗
- 둥근 카드 남발 ✗ (반경 4px, 카드 자체를 최소화)
- 얼굴 있는 AI 아바타 ✗ — **나레이션이 "기계는 체험할 수 없다"고 말하는데 얼굴을 주면 그 문장이 무너진다**
- 타이핑 애니메이션 ✗
- **대화 중에는** 캐릭터를 UI에 넣지 않는다 — 진입 화면 `A1`에서 한 번 인사하고 물러난다 (7-2 참조). 그 외 캐릭터의 자리는 인쇄물·영상·부스 사인물

## 7-1. 화면은 하나다 — 모바일 390×844

**데스크톱 레이아웃을 따로 만들지 않는다.**

작품은 모바일 앱이고, 부스는 그 앱을 **맥북 화면 가운데 폰 프레임으로** 띄운다.
넓은 화면에서는 어둠이 프레임 주위를 채울 뿐, 레이아웃이 바뀌지 않는다.

```
맥북 1440×900
┌───────────────────────────────────────────┐
│                                           │
│              ┌─────────────┐              │
│              │             │              │
│              │  390×844    │   ← 앱 화면   │
│              │             │      그대로   │
│              │             │              │
│              └─────────────┘              │
│                                           │
│  輝敍                    이 사진은 지워집니다 │
└───────────────────────────────────────────┘
      ↑ 어둠 #100D16. 프레임 주위엔 아무것도 없다
```

### 프레임 밖(맥북 여백)에 놓이는 것 — 딱 둘
| 위치 | 내용 |
| :-- | :-- |
| 왼쪽 아래 | `輝敍` 마크. 12px, `--dim` |
| 오른쪽 아래 | "이 사진은 세션이 끝나면 지워집니다" 12px, `--dim` |

그 외에는 **비운다.** 프레임 주위를 설명이나 장식으로 채우면 폰 화면이 작아 보인다.
프레임에 기기 목업(베젤·노치 그림)을 그리지 않는다 — **어둠 위에 화면만 떠 있다.**

### 왜 이게 이득인가
- 아트보드가 **한 벌**이다. 화면 9장을 두 번 그리지 않는다
- 부스에서 보이는 것이 곧 **포트폴리오에 실리는 앱 화면**이다. 따로 만들 것이 없다
- 폰에 설치했을 때와 부스에서 볼 때가 **같은 화면**이라 작품 설명이 단순해진다

### 폰에서만 주의할 것
- 입력창은 **하단 고정**. 키보드가 올라와도 사진이 완전히 가려지면 안 된다 → 사진은 축소되되 사라지지 않는다
- 안전영역(노치·홈 인디케이터) 여백 확보
- PWA 전체화면이므로 **브라우저 뒤로가기가 없다** → 화면 안에 나가는 길이 있어야 한다
- 설치 아이콘·스플래시는 어둠 `#100D16` 바탕에 등불
- 부스는 물리 키보드를 쓰므로 화상 키보드가 안 뜬다 → **키보드 없는 상태가 부스의 기본 화면**

## 7-2. 앱 진입 플로우 (PWA 전용)

> **원칙: 진입은 복도지 목적지가 아니다.**
> 이 제품은 챗봇이다. 대화 화면이 제품이고, 앞의 화면들은 거기까지 데려다주는 통로다.
> **진입 화면은 대화 화면보다 시각적으로 약해야 한다.** 여기서 힘을 주면 정작 본편이 밋밋해 보인다.
> 설치 후 첫 실행부터 대화 시작까지 **15초 안에** 끝나야 한다.

```
A0  언어           ENG / KOR — 두 글자만. 어둠 위에 텍스트 둘
     ↓
A1  휘서의 인사     캐릭터 등장 + 자기소개 2~3줄
     ↓
S1  사진 올리기     "○○년 사진 한 장을 보여주세요"
     ↓
S2  확인 → S3 대화 → S4 이야기 → S5 종료
```

### A0 · 언어
- 화면 전체에 **`ENGLISH` / `한국어` 두 줄뿐.** 국기·아이콘·설명 없음
- 첫 실행에만 뜬다. 이후엔 설정에서 바꾼다
- 전시 부스에서는 이 화면을 **띄우지 않는다** — 대기 화면 구석에 작은 토글로 둔다 (관람객 앞에 단계를 늘리지 않기 위해)

**언어 선택이 정하는 것은 휘서가 답할 언어뿐이다. 사용자는 아무 언어로나 답해도 된다.**
(이중언어 사용자가 영어로 생각하다 한국어 단어를 섞는 것은 자연스럽다. 막을 이유가 없다.)

**대화까지 영어를 지원한다** — 국제대 전시라 실제로 필요하다.
프롬프트를 두 벌 만들지 않는다: 질문 전략 규칙(꼬리물기·채널만 열기·단정 금지)은 언어와 무관하므로
`ask.v1.md` 하나에 `{{LANGUAGE}}` 지시를 넣는다. 다만 아래는 언어별로 갈린다.

| 항목 | 내용 |
| :-- | :-- |
| 톤 지시 | 한국어는 존댓말 체(해요체/합니다체) 결정이 있고, 영어는 formal/casual 레지스터. 언어별 한 줄씩 |
| 예시 문장 | 프롬프트에 한국어 예시를 넣으면 영어 출력이 끌려간다 → 언어별로 두거나 예시 없이 규칙만 |
| 세리프 | 영어엔 명조가 없다. **Lora / Newsreader / Source Serif** 중 택1 (Noto Serif KR와 짝) |
| 글자 길이 | 영어가 20~30% 길다 → 버튼·라벨 폭, **특히 58mm 영수증 줄바꿈** |
| 테스트 | 영어 세션을 실제로 돌려본다. 한국어 품질이 영어 품질을 보장하지 않는다 |

### A1 · 휘서의 인사 ★ 캐릭터가 유일하게 등장하는 자리
Teams 가이드 원문: *"It's critical that your bot introduces itself and describes what it can do.
This initial exchange helps people get comfortable interacting with it."*

- **캐릭터(초)가 여기서 한 번 나온다.** 자기가 누구고 무엇을 하는지 2~3줄
- 화면을 넘길 때마다 카드가 바뀌는 튜토리얼 ✗ — **한 화면에서 문장만 이어진다**
- "건너뛰기"를 눈에 띄게

**그리고 대화가 시작되면 캐릭터는 화면에서 사라진다.**

> 7장 안티패턴의 "캐릭터를 UI에 넣지 않는다"는 **대화 중**의 규칙이다.
> 이유: 기계가 표정을 갖고 반응하면 "기계는 체험할 수 없다"는 이 프로젝트의 문장이 무너진다.
> 안내자로 한 번 나왔다가 물러나는 것은 그 문장을 오히려 강화한다 —
> **빛이 데려다주고 자리를 비켜준다.** 그 자리에 남는 것은 사람의 사진과 사람의 말이다.
> 대화 중 휘서의 존재는 얼굴이 아니라 **질문과 연보라 면**으로만 드러난다.

## 8. 화면 목록

**턴 수는 디자인 대상이 아니다.** 전시 3턴 / 다큐 무제한은 서버가 세는 파라미터이고,
화면은 어느 쪽에서도 같다. 아래 목록은 앱 전체의 화면이며, 전시에서만 쓰이는 것을 따로 표시했다.

**본체 (맥북 1440×900 / 폰 390×844 — 같은 화면의 두 폭)**

| | 화면 | 1차 층 | 색 상태 |
| :-- | :-- | :-- | :-- |
| A0 | 언어 *(앱 첫 실행만)* | 두 줄의 글자 | 어둠만 |
| A1 | 휘서의 인사 *(앱 첫 실행만)* | 캐릭터 | 연보라 |
| S0 | 대기 *(전시)* | 등불 | 어둠만 |
| S1 | 사진 요청 | QR *(전시)* / 파일 선택 *(개인)* | 연보라 |
| S2 | 확인 | 사진 | 연보라 |
| **S3** | **대화** | 질문 | 앰버 면이 늘어남 |
| S4 | 이야기 | 한 줄 정리 | 앰버 |
| S5 | 종료 | 등불 | 앰버 → 어둠 |

S3 하나가 전체의 대부분이다. 턴이 3번이든 열 번이든 **같은 화면이 반복될 뿐이다.**

**전시 전용 추가 화면 (관람객 폰, 설치 없이 브라우저)**

| | 화면 | 내용 |
| :-- | :-- | :-- |
| P1 | 올리기 | 버튼 하나 + 개인정보 한 줄 |
| P2 | 완료 | "화면을 봐주세요" |

**영수증 (58 또는 80mm) — 전시 전용**

| | 내용 |
| :-- | :-- |
| R1 | 사진(도트) · 시기 · 문답 요약 · 한 줄 정리 · "이 사진은 지워졌습니다" |

### 모드에 따라 갈리는 것 (디자인 아님)
- 턴 수 상한
- 사진을 받는 경로 (QR ↔ 폰 자체 파일 선택)
- 종료 처리 (영수증 출력 ↔ 화면에서 끝)
- 무입력 자동 초기화 (전시만)

> 관람객 폰의 `P1·P2`는 **설치하는 앱이 아니라** QR로 열리는 업로드 전용 페이지다.
> PWA로 설치되는 것은 본체 `S0~S5` 쪽이다.
