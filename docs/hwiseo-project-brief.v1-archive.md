# 휘서 (輝敍) — 프로젝트 기획 초안

> 잠든 사진에 빛을 비춰, 기억을 이야기로 펼쳐내는 AI 회상 서비스

- **작성일**: 2026-08-24
- **타임라인**: 졸업 전시까지 약 6주
- **형태**: 웹앱 + 전시 부스 + 실사용 검증 + 관찰 다큐

---

## 1. 이름과 컨셉

- **輝 (빛날 휘)**: 어둠(클라우드)에 묻힌 사진·기억에 빛을 비추는 것 = 회상 세션
- **敍/叙 (펼 서, 서사·서술의 서)**: 꺼낸 기억을 이야기로 펼쳐내는 것 = 이야기 생성
- 컨셉 문장: **"묻힌 기억을 비춰(輝), 이야기로 펼쳐낸다(敍)"**

### 워딩 주의
- ❌ "어두운 기억" — 트라우마로 읽혀 윤리 공격 유발
- ✅ "어둠 속에 **묻힌/잠든** 기억" — 기억 자체는 빛나는데 안 보일 뿐

### 표기 결정 대기
- 敍 (정자, 격 있음, 輝와 무게 균형) vs 叙 (획 적어 로고로 깔끔) → 로고 시안 단계에서 둘 다 놓고 결정

---

## 2. 문제정의 (사회적 가치)

**"사진은 폭증했는데, 기억의 전승은 끊겼다."**

1. 필름 시절: 인화 → 앨범 → 가족이 둘러앉아 함께 봄. 사진 = **대화의 매개체**
2. 현재: 연간 수만 장 촬영, 클라우드에 묻힘. 재열람은 혼자 스크롤
3. 사라진 것: 사진이 아니라 **사진을 놓고 오가던 세대 간 대화** (구술 기억)
4. 결과: 부모 세대의 이야기가 기록 없이 소멸. 물어볼 수 있는 시간은 유한함

- 도입부: 사진 인화량 감소 (누구나 즉시 공감)
- 착지점: 세대 간 기억 전승 단절 = 무형 유산 아카이빙 문제 (고령화·가족 해체와 연결)
- 구조: 개인 불편 → 구조적 손실로 번역

---

## 3. 철학 챕터 (World → Image → Language)

> AI는 세계를 언어로만 본다. 인간은 세계를 살았다.
> 사진은 세계의 조각이지만, 그 완성은 경험한 사람의 언어로만 가능하다.
> 휘서는 이미지를 읽고 질문을 던져, 어둠 속에서 "반짝" 떠오르는 기억을 —
> 그 사람만이 쓸 수 있는 이야기로 펼쳐낸다. 輝敍.

### 역할 분담 (AI 대체 논란 방어)
- **AI**: 이미지를 읽고 **질문**을 만든다 — 언어로 가는 문을 두드림
- **인간**: 경험을 언어로 꺼낸다 — 문을 여는 건 기억의 주인만 가능
- **AI (敍)**: 꺼내진 언어를 이야기로 펼친다 — 지어내지 않고 재구성만

### 빛의 삼중 스케일 (패널 핵심 구조)
1. **머릿속**: "뭐였지…" 하다 반짝 떠오르는 찰나 (인지)
2. **화면**: 사진에 조명, 풍등이 떠오름 (인터페이스)
3. **공간**: 어두운 부스의 조명 (전시)

### 오감
- 사진은 시각만 담는 매체 → **AI의 질문이 나머지 사감(냄새·소리·촉감·맛)을 채운다**
- 이미지에 없는 것을 질문이 불러냄

## 4. 서비스 구조

### 핵심 플로우
```
사진 업로드 → 회상 세션(輝) → 이야기 생성(敍) → 건넴 선택
```

### 건넴 선택 3가지 (세션 종료 화면)
1. **지금, 누군가에게** (전승) — 수신자 자유 지정
2. **미래의 나에게** (타임캡슐) — 예약 발송, 1년 뒤 등
3. **그냥 간직하기** (아카이브)

- 敍 기준으로는 간직만 해도 컨셉 완성 (이야기가 펼쳐진 순간) → 세 선택지 동등하게 성립
- 타임캡슐: 재방문 트리거 ("작년의 당신이 보낸 이야기가 도착했어요") + 도착한 이야기가 새 회상 세션의 시작점 → 아카이브가 나이테처럼 쌓임

### 타겟 전략
- **설계**: 관계 불문 (기억을 가진 사람 ↔ 건네받고 싶은 사람)
- **서사·검증**: 세대 간으로 좁혀서 집중 (문제정의 논리가 세대 차이에 기반)
- **확장성**: 패널 마지막 1장 — "구조상 부부·친구·미래의 나로 확장"
- 화법: "지금은 세대 간 전승에 집중했지만 관계 축은 열려 있다"

---

## 5. 화면 설계 (5개 화면)

### 5-1. 시작 — 사진 업로드
- 옛 사진 1~10장 업로드
- AI 메타 분석: 연대(옷·화질·배경), 장소 유형, 인물 수·관계, 상황
- UX 포인트: 단정하지 않고 확인받는 톤 — "1980년대 후반, 야외 행사로 보여요. 맞나요?"

### 5-2. 대화 — 회상 세션 (서비스의 심장)
질문 3층 구조:
| 층 | 유형 | 예시 | 역할 |
|---|---|---|---|
| 1층 | 사실 | "이날 어디였어요?" | 부담 없이 입 열기 |
| 2층 | 감각 | "그날 냄새 기억나요?" | 감각 단서로 기억 열기 (회상요법 근거) |
| 3층 | 의미 | "그때의 나에게 해주고 싶은 말?" | 이야기의 깊이 |

- **꼬리물기 규칙**: 답변에서 새 단서가 나오면 준비된 질문 대신 그 단서를 따라감 → 스크립트 챗봇과의 결정적 차이 = "왜 굳이 AI냐"의 답
- 한 세션 = 질문 5~7개, 10분 내외 ("한 사진 = 한 세션" 리듬, 어르신 피로 관리)

### 5-3. 생성 — 이야기 조각
- 답변을 1인칭 구어체 이야기로 정리
- **환각 통제 원칙**: 발화된 내용만 재구성, 살 붙이지 않음 (프롬프트에 명시)
- 생성 후 사용자 수정 단계 필수 → "AI 환각을 UX로 통제" 논점

### 5-4. 아카이브 — 건네받는 쪽
- 사진 + 이야기 + 음성 원본이 카드로 쌓임
- 정렬: 업로드순 ❌ → **이야기 속 연대순** (한 사람의 연대기가 됨)
- 전시 책자의 원본 데이터

### 5-5. 전시 모드 (별도 빌드)
- 미리 생성한 대화 세트로 도는 **오프라인 버전**
- 샘플 사진 3개 중 선택 → 캐시된 질문 → 준비된 분기 안에서 3분 체험
- 네트워크 죽어도 돌아가는 게 존재 이유. **라이브 API는 보너스, 캐시 데모가 본체**

### 어르신 대상 UI 원칙
- 글자 크게, 화면당 행동 하나, 뒤로가기 항상 같은 자리
- 에러 메시지 대신 대화형 복구 ("다시 한번 말씀해주세요")
- 세션 중 화면은 사진이 주인공, UI는 사라질 것

## 6. 시그니처 모션 — 풍등

- ❌ 디즈니 불꽃놀이 인트로 — 표절 리스크 + 불꽃은 "터지고 사라지는 빛"이라 컨셉 불일치
- ✅ **풍등**: 건네져서 도착하는 빛. 동양적 정서 = 한자 이름과 결 맞음

### 모션 설계
- **전송**: 사진과 이야기가 빛 덩어리로 응축 → 화면 아래에서 천천히 떠오름 → "2027년 8월에 도착합니다"
- **수신**: 어두운 화면에 빛이 내려옴 → 터치하면 펼쳐지며 사진과 이야기 등장
- 보내는 쪽 상승 ↔ 받는 쪽 하강 = 한 쌍, 역재생 구조 (디자인 시스템으로 깔끔)

### 구현
- CSS/JS 파티클로 충분 (tsParticles, Framer Motion)
- 3D·영상 합성 금지 — 어두운 배경 + 빛 입자는 단순할수록 예쁨
- 다큐 영상 엔딩 컷으로도 사용 (이야기가 등불로 떠오르며 끝)

## 8. 전시 구성 (부스 = 비유를 연기하는 공간)

```
입구(어둠) → 중앙(조명·체험) → 출구(건넴)
```

1. **입구 — 어둠**: 어두운 부스, 흐리게 인쇄한 사진 수백 장. 카피: "당신 클라우드에 잠든 32,000장"
2. **중앙 — 조명**: 태블릿 전시 모드 데모, 3분 체험
3. **출구 — 건넴**:
   - 가족 실사용 결과물 **실물 책자** (인화·제본) — 디지털로 시작해 물성으로 끝나는 수미상관
   - **관찰 다큐 2~3분** 프로젝션
   - 참여 코너: "1년 뒤 나에게 한 줄" → 실제로 1년 뒤 이메일 발송 (전시의 여운 설계)

## 9. 관찰 다큐 (2~3분)

- **원칙: 새 작업 추가 ❌, 3~4주차 실사용을 카메라로 담기 ⭕**
- 내용: 부모님이 질문에 답하다 "아 이거…" 하며 이야기가 터지는 순간, 표정과 침묵
- 역할: ①"굳이 왜 씀?" 방어 최강 형태 ②체험 안 하는 관람객의 메인 전달 매체 ③부스 프로젝션
- 장비: 스마트폰 + 삼각대 + 핀마이크 (장비 욕심 금지)
- 촬영: 실사용 세션 중 2회만 / 편집: 5주차 이틀 상한 ("이틀 넘으면 현재 버전 확정")
- ⚠️ **촬영 전 출연 동의 + 공개 범위 편집 전 합의 필수**

## 10. 6주 타임라인 (역산)

| 주차 | 할 일 | 산출물 |
|---|---|---|
| 1주차 | 데스크리서치(인화량 감소, 재열람률) + 인터뷰 5~8명 | 문제정의 근거 데이터 |
| 2주차 | 페르소나·저니·IA·와이어프레임 + **프롬프트 설계 시작** | 프롬프트 = 디자인 산출물로 패널 게재 |
| 3~4주차 | 웹앱 구현 + 실사용 (세대 간 2~3가족 + 기타 관계 1건) + 다큐 촬영 2회 + **2주 타임캡슐 실증** | 실사용 기록 = 검증 챕터 |
| 4주차 | 패널 시안 절반 미리 제작 | 5주차 부하 분산 |
| 5주차 | 패널 완성 + 책자 인화·제본 + 다큐 편집(이틀 상한) + 전시 모드 빌드 + 시연 영상 | 전시물 일체 |
| 6주차 | 셋업 + 버퍼. **부스 조도 리허설 필수** (조명이 컨셉이므로) | — |

### 타임캡슐 검증 방법
- 실사용에서 "2주 뒤 도착"으로 압축 세팅 → 3주차 발송분이 5주차 도착하는 것을 실증
- 전시에서는 "1년 뒤" 시나리오를 영상/목업으로 → "기간은 변수, 구조는 검증됨"

## 11. 예상 크리틱 Q&A (방어 논리)

### Q. "유저가 굳이 왜 씀?"
- 데일리 앱 아님 → **의식(ritual)형 서비스** (명절, 생신, 앨범 발견). 빈도 아닌 깊이로 승부
- **비대칭 동기 선제 공개**: 자식이 시작하고 부모가 답하는 구조로 설계했다고 먼저 말하기
- **손실 회피**: "지금 안 물어보면 영영 못 물어봄" → 인터뷰로 검증해 수치 확보

### Q. "왜 굳이 AI야?"
- 회상 질문은 사람마다 완전히 달라 스크립트 불가 + 답변 단서를 따라가는 꼬리물기
- 철학 챕터로 최종 방어: AI는 촉매, 번역(경험→언어)은 인간만 가능

### Q. "AI가 인간의 이야기를 대체하는 것 아니냐?"
- 역할 분담 구조 + "발화된 것만 재구성" 프롬프트 원칙 + 사용자 수정 단계

### Q. "컨셉이 화면 어디에 있죠?"
- 輝 = 회상 세션, 敍 = 이야기 생성 — 컨셉이 정보 구조 그 자체
- 빛의 삼중 스케일 (인지·인터페이스·공간)

### Q. "타겟이 누구냐 / 너무 좁지 않냐"
- 세대 간으로 좁혀 찌르고, 확장성(부부·친구·미래의 나)은 마지막 1장
