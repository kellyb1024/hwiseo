### 배경 영상 이틀 작업 순서

1. **나레이션 오디오를 가장 먼저 잠근다.** (화요일 오전)
   애니메이션은 오디오에 붙는 것이라, 길이가 안 정해진 상태에서 그림부터 그리면 전부 다시 맞춰야 한다.
   v3.1에 파트별 시간(0:00–0:40 / 0:40–1:22 …)이 이미 잡혀 있으므로 그 위에 얹는다.
2. **C1부터 완성도 높게 가지 않는다.**
   전체를 러프로 한 바퀴(타이밍·배치만) 돌린 뒤 남은 시간에 디테일을 올린다.
   → 어느 시점에 멈춰도 끝까지 있는 영상이 남는다. C1~C3만 공들이면 뒤가 텅 빈다.
3. **C7(輝 → 敍 모핑)이 함정.**
   획이 풀려 연속 변형되는 연출은 시간을 가장 많이 먹는데 화면에는 2초 나온다.
   대안을 미리 정해둘 것 — 輝가 빛으로 흩어졌다 敍로 다시 모이는 방식이면 훨씬 빠르고
   스토리보드의 '빛' 컨셉에도 어긋나지 않는다.
4. **자막 시간을 예산에 넣는다.** 파트당 5~6줄, 압축 불가능한 노가다. 마지막에 몰면 반드시 초과.

> 유리한 점: v3.1이 **흰 선 하나 / 어둠 / 미니멀**로 설계돼 있어 프레임 단가가 낮고 에셋 재사용률이 높다.

### 프로토타입 1차의 정의 — 대화 '품질'이 아니라 '완주'
프롬프트 튜닝은 W3~W4의 일이다. 프롬프트는 코드가 아니라 텍스트이므로 **교체 비용이 거의 0**.
9/3에 증명할 것은 **세션 하나가 끊기지 않고 끝까지 간다**는 사실 하나다.

| | 항목 |
| :-- | :-- |
| **넣는다** | 사진 업로드 / 사진 → 첫 질문 생성 / 답변 → 다음 질문 (5~7턴, 꼬리물기) / 종료 → **텍스트 이야기** 출력 |
| **뺀다 (2차)** | **4컷 이미지 생성** ★ / QR 페어링 (1차는 파일 업로드) / 전시 모드 / 폴백 처리 / 디자인 마감 |

> **4컷을 빼는 이유:** 이미지 모델 결과는 예측 불가 + 사진체 금지 제약으로 시행착오 필수.
> 여기 물리면 9/3에 아무것도 못 보여준다. 브리프에도 폴백(텍스트+원본 사진)이 준비돼 있다.
> 4컷이 반쯤 나오는 것보다 "질문이 오고 → 답하면 다음 질문이 오고 → 내 이야기가 나온다"가
> 실물로 도는 편이 논지가 선명하다.

**프롬프트 v0는 새로 짜지 않는다** — 브리프 5-2의 3층 구조(사실/감각/의미) + 1차 세션 테스트 규칙 8개로 조립.

※ 수동 UT는 W3으로 이월.
